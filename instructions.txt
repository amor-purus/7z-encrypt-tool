7z 文件加密工具 v1.5.0 — 简体中文使用说明

官方仓库：https://github.com/amor-purus/7z-encrypt-tool
下载页面：https://github.com/amor-purus/7z-encrypt-tool/releases/latest
适用平台：Windows 11 x64

一、下载与启动
1. 打开上面的 Releases 下载页面，找到最新正式版本。
2. 下载 7z-encrypt-tool-windows-x64.exe 和 SHA256SUMS.txt。
3. 可用 PowerShell 的 Get-FileHash 命令验证 EXE 的 SHA-256，并与 SHA256SUMS.txt 中的值比较。
4. 双击 EXE 运行；不需要单独安装 Python、pip、BAT 启动器或管理员权限。
5. EXE 未使用受信任的代码签名证书。Windows 可能显示“未知发布者”或 SmartScreen 提示；请先核对下载来源与文件校验值，不要在来源不明时绕过安全警告。
注意：校验和可以发现文件差异，但不能独立证明发布者身份。

二、添加待加密的内容
1. “添加文件”可一次选择多个文件；“添加文件夹”每次添加一个文件夹，可重复操作。
2. 文件与文件夹可以混合选择。选中父文件夹时，其内部文件或子文件夹不会重复打包。
3. “移除选中”移除列表中选定的项目，“清空”移除全部待处理项目。
4. 程序保留选定文件夹的子目录、文件和空文件夹，并尽量避免同名路径冲突。

三、生成加密压缩包与单独保存密码
1. 点击“开始加密”，先选择 .7z 压缩包的输出目录。
2. **再选择另一个目录，用来保存明文密码 TXT。两个目录必须不同。**
3. 程序会提示 TXT 包含完整的明文密码，只有明确确认后才继续。
4. 程序自动生成32字符随机密码和随机压缩包文件名。
5. 执行 AES-256 7z 加密，隐藏压缩包内部文件名，然后校验归档内容与完整性。
6. 成功后，压缩包与密码 TXT 分别出现在用户选择的两个目录中。已有同名密码文件不会被覆盖。

重要：从 v1.3.0 起，密码 TXT **不再自动保存在压缩包旁边**。此前 v1.2.0 的同目录说明已经过时。明文 TXT 是恢复密钥，必须妥善保管，不应与压缩包一起随意上传、分享或同步到公开位置。丢失密码可能无法恢复文件。

四、数据安全和异常恢复
- 源文件不会被删除、移动或修改。
- 压缩包的输出位置不得位于被加密源目录内部，避免递归打包。
- 程序会检查压缩包文件头是否加密，并验证预期归档成员。
- v1.5.0 引入异常退出恢复机制：下一次运行会检查本地事务记录，尽力清理未完成输出和确认没有正式归档的孤立密码记录。
- 若文件身份、目录可访问性等状态不明确，程序会停止可能破坏数据的清理并提醒处理。
- 这种恢复机制不保证跨两个目录的完全原子提交，也不能消除硬件断电、磁盘损坏的风险。请勿将唯一副本直接用于测试。

五、下载验证与构建来源
- 正式版下载：Releases 页面（不建议非开发人员下载 GitHub 源码 ZIP 来代替 EXE）。
- 正式版附带 SHA256SUMS.txt、BUILD-INFO.txt 和依赖信息，便于确认文件与构建来源。
- 当前发布的 Windows EXE 没有 Authenticode 签名；这是项目已记录的决定。
- GitHub Actions 会在 Windows 上构建 EXE、运行源码测试及冻结后自测，再准备发布文件。
- 详细说明参见 README.md、BUILD_REPRODUCIBILITY.md、CODE_SIGNING.md 和 CHANGELOG.md。

六、遇到问题时
1. 记下正在执行的操作及出现的提示；不要把明文密码或真实敏感文件直接发给他人。
2. 错误弹窗可截图反馈，但请遮盖个人信息和文件路径。
3. 如需要日志，可按 Win + R，输入：
   %LOCALAPPDATA%\7z-Encrypt-Tool\logs
4. 日志可能包含本机路径；分享前务必检查和删去敏感信息。
5. 反馈时说明 Windows 版本、软件版本、预期结果与实际结果。

七、技术与许可
- 本项目的开发与构建文档在 GitHub 仓库中。
- 本工具用于保护有权处理的文件，用户自行负责妥善保管恢复密码。
- 源码是否允许修改或再分发取决于仓库的 LICENSE 或另行获得的授权；“仓库公开”本身不等于授予开源许可。
